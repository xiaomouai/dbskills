# 架构

系统只保留两个部件：负责判断与执行的 Skill，以及负责记录确定状态的工作台。

```text
需求与流量 → 商业策略 → 内容 ─────────┐
                     销售 → 交付/复购 ├→ 验收 → 规则回写
                                      ┘
```

业务档案是唯一真源。每个角色读取同一产品、付款人、购买场景、报价和证据，不自行创造定位。工作台只保存任务、依赖和产物，不调用模型、不自动发布、不发送消息。

完整模式包含六个角色；内容和销售可在策略完成后并行，交付依赖销售，最终验收依赖内容与交付。没有多 Agent 能力时，同一 Agent 可以按角色顺序执行，但必须如实标记。

验收分两层：`verify` 检查本地依赖和产物；商业验证另查公开状态、有效咨询、报价、已收款、退款与续费。前者不能代替后者。
