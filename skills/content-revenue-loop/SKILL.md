# 内容商业闭环

目标不是增加内容数量，而是让每条内容连接一个可验证的购买场景，并把真实成交结果写回下一轮决策。

```text
需求证据 → 流量入口 → 内容承接 → 合格线索 → 报价成交
    ↑                                      ↓
规则回写 ← 复购/转介绍 ← 交付验收 ← 已收款
```

## 先恢复当前状态

读取当前对话和可用业务资料，提取产品、付款人、使用者、购买触发、替代方案、报价、交付能力、渠道、已有内容、线索、订单、退款和目标。已有信息不重复询问。

区分五种状态：事实、推断、待验证、平台提交、真实商业结果。曝光、互动、下载、注册、体验、报价、付款与续费分别记录，不相互冒充。

只在一个缺口会改变当前任务或验收时追问一个问题。信息不足但可安全推进时，明确假设并完成不依赖答案的部分。

## 判断当前唯一断点

按最早断点行动，不预设每次运行完整流程：

| 断点 | 证据 | 当前任务 |
|---|---|---|
| 产品与付款人不清 | 无法写出谁在什么场景为何付费 | 需求验证 |
| 有需求、无稳定触达 | 找不到同类买家或内容无有效到达 | 流量入口 |
| 有曝光、无有效咨询 | 内容与购买场景、证据或行动入口断开 | 内容承接 |
| 有咨询、无报价 | 线索不合格或需求确认不足 | 线索资格 |
| 有报价、无付款 | 结果、信任、价格、时机或风险有问题 | 销售成交 |
| 有付款、交付失控 | 范围、成本或验收不清 | 交付 |
| 有交付、无续费/转介绍 | 持续价值或复购场景不足 | 留存 |

互动多但没有购买证据时，优先修复最早断点，不扩大内容产量或投流。

## 建立最小业务真源

有文件系统时保存一份业务档案；没有时在本轮输出中维护。至少包含：

- 产品、付款人、使用者和不适用人群；
- 购买触发、问题成本、现有替代方案和客户原话；
- 交付物、周期、价格、直接成本、付款与验收；
- 能力证据、事实限制、禁止承诺和合规要求；
- 主渠道、行动入口、当前漏斗数据和统计窗口。

同一账号保持一个清晰购买场景。不同付款人或明显不同产品分别建立闭环，不把数据混进同一漏斗。

## 流量

先确定买家在问题发生时会去哪里、搜索什么、询问谁。流量来源可以是搜索内容、推荐内容、公开需求回应、合作转介绍、社群、活动或付费推广。

每个来源记录：渠道、买家意图、可触达规模、成本、规则限制、目标动作和归因方式。招聘、讨论热度和竞品销量只能作为需求线索，不能证明本产品有人付款。

自然流量和直接沟通先形成基线。只有某内容或人群已经带来合格线索，且产品毛利允许时，才小额测试付费推广。测试前写明预算上限、窗口、唯一变量和停止条件。

## 内容

每条内容先填任务卡：目标买家、具体场景、唯一问题、核心判断、证据、对应产品、行动入口和目标指标。

内容只承担一种主要任务：识别问题、帮助选择、展示能力、解除顾虑或推动行动。结构可按“场景 → 判断 → 方法/演示 → 证据 → 边界 → 下一步”删改。

同一事实可以适配多个平台，但不能机械复制。平台形式、用户意图和承接入口不同，应分别改写。没有真实案例时使用明确标注的演示样本；不虚构用户、效果、订单、评价或稀缺性。

## 线索与销售

合格线索必须同时具备：目标客户匹配、具体待解决问题、愿意继续沟通。预算、决策权和时间表在进入报价前补齐；个人消费者按实际购买链路简化。

首次沟通只确认问题和适配性。报价写清客户、结果、交付、周期、价格、付款节点、验收和不包含事项。拒绝或要求停止时结束跟进。

线索阶段最少使用：新线索、已确认需求、已报价、已付款、已交付、续费/转介绍、失败。每条记录负责人、来源内容、下一步、日期和失败原因。

## 交付与复购

付款不代表闭环完成。记录实际交付工时、直接成本、验收、退款、使用或激活、客户反馈。把交付中重复出现的问题、异议、案例和方法写回内容素材。

只有产品存在持续价值且客户实际使用后，才设计订阅或续费。转介绍在客户确认结果后提出，不以奖励诱导虚假评价。

## 最小台账与指标

只需四张表：

1. 证据：客户原话、来源、日期、证据等级和待核验项。
2. 内容：内容编号、平台、产品、任务、状态、链接和结果。
3. 线索：来源内容、资格、阶段、报价、下一步和失败原因。
4. 订单：已收款、退款、成本、工时、验收、使用、续费和转介绍。

核心计算：有效咨询率、报价率、付款率、退款率、获客成本、单客贡献毛利、实际净时薪、续费率。分母为零时写“不适用”；数据未接入时写“未获取”，不能填零。

## 多角色执行

单一能力能解决当前断点时只用一个角色。复杂任务最多安排一个主角色和两个必要辅助角色：

- 主角色负责当前断点、统一交付和停止条件；
- 证据角色只补充决定结论的需求、渠道或竞品事实；
- 验收角色只检查事实、漏斗关联、权限和结果口径。

有多 Agent 工具时可并行无依赖工作；存在依赖时必须顺序执行。没有多 Agent 工具时，由同一 Agent 分角色执行并明确说明，不能称为独立复核。所有角色共享业务真源，最终交付一份结果，不拼接互相矛盾的报告。

## 验收与停止

每轮必须输出：当前断点、事实与缺口、完成产物、指标窗口、结果状态、唯一下一步和停止条件。

结构通过不等于商业通过。商业证据强度为：已收款与低退款、复购/续费、明确报价请求、合格销售沟通、有效咨询、互动。具体阈值应根据客单价、周期和样本设定；没有基线时把阈值标为实验规则。

发布、私信、投流、创建订单或其他外部动作只在用户明确授权且工具可用时执行。平台返回“提交成功”时记录为已提交；只有公开链接或可核验状态才记录为已发布。
